CP12 Godot Capstone

How Your Game Studio Shares Work

This guide shows your group how to work together on a Godot game without losing files, overwriting scenes, or depending on GitHub Desktop.

Recommended for most groups

Use Google Drive as the main workspace. It is easier for sharing images, sounds, 3D models, screenshots, planning, and final ZIP files.

Optional evidence upgrade

Use GitHub for checkpoints. GitHub is useful for code history, README notes, and small project files, but it is not ideal for huge game assets through the browser.

The Big Rule

Do not have every group member editing the same Godot project at the same time.

Godot projects are made of scenes, scripts, assets, imports, and settings. If everyone changes the same files, your group can accidentally break or overwrite the project.

1

Plan

Decide roles and features.

2

Build

Each person makes one assigned part.

3

Share

Upload code, art, audio, or scenes to Drive.

4

Integrate

One person adds approved work into the master project.

5

Test

Run the game, fix bugs, and record evidence.

Which System Should Your Group Use?

Easier / Recommended

Best for beginner groups. Use this when you need the simplest possible system.

WeaknessLess code history than GitHub
Optional / Advanced

Best for groups that can handle extra steps. GitHub becomes your process portfolio.

Best forScripts, README, dev log, screenshots, small scenes, code checkpoints

Teacher recommendation

Start with Google Drive Only. Add GitHub only after the group understands how to organize and share files.

Step 1: Create the Google Drive Group Folder

One student creates the main folder and shares it with all group members and the teacher.

CP12_Godot_Game_GroupName
01_PlanningProposal, task list, game idea, roles
02_AssetsImages, sprites, sounds, models
03_Code_SnippetsScripts and code notes
04_Feature_HandoffsSmall scenes or features ready to be added
05_Screenshots_TestingBug evidence, screenshots, test notes
06_Final_SubmissionFinal ZIP, final reflection, final links

Drive sharing rule

The folder should be shared with group members as Editor and shared with the teacher so progress can be checked.

Step 2: Choose Group Roles

Role

Project Manager

Keeps the task list updated and makes sure the group knows what to do next.

Role

Godot Integrator

Controls the master project and adds approved work from the group.

Role

Code Lead

Works on movement, scoring, collisions, UI, enemies, or other scripts.

Role

Asset Lead

Creates or finds images, sprites, audio, 3D models, and interface assets.

Role

Tester

Runs the game, finds bugs, takes screenshots, and records what needs fixing.

Role

Documenter

Writes the daily log and gathers evidence for the final submission.

Scene ownership rule

Only one person should edit a major scene such as MainLevel.tscn at a time. Other students should send assets, scripts, or small feature scenes to the Integrator.

Step 3: Daily Class Workflow

Start of class

Plan the work

Open the task list. Decide who is doing what today. Make sure two people are not editing the same scene.

During class

Build and share

Work on your assigned part. Upload assets, code, screenshots, or feature handoffs to Google Drive.

End of class

Test and document

The Integrator saves the master project. The group tests the game and writes the dev log.

How to Share Code

Do not just paste random code into the group chat. Put code in the 03_Code_Snippets folder with instructions.

File name example:
ava_player_movement_june5.txt

Feature:
Player movement

Put this script on:
Player.tscn

Required input actions:
move_left
move_right
jump

Code:
Paste your code here.

Known bugs:
The player slides too much after landing.

main_menu_background.jpg
Bad file names 
image1.png
new thing.png
finalfinal.png
download.png
untitled.wav

Large file rule

Large files such as .glb, .blend, .mp4, and high-resolution images should stay in Google Drive.

How to Hand Off a Godot Feature

If you build a small part of the game, do not send the entire project. Send only the files needed for that feature.

Folder name example:
liam_enemy_chase_june5

Include:
Enemy.tscn
enemy_chase.gd
enemy_robot.png
README.txt

README.txt should explain:
1. What the feature does
2. Which files are included
3. Where the files should go
4. How to test the feature
5. Any known bugs

Optional: GitHub Setup for Checkpoints

Use this only if your group is ready. GitHub is not replacing Google Drive. It is for checkpoint evidence.

1

Sign in

Go to GitHub and sign in or create an account.

2

New repo

Create a repository named cp12-godot-groupname.

3

Add README

Add a README.md file explaining the game and group roles.

4

Upload files

Use Add file → Upload files for scripts, small scenes, screenshots, and notes.

Important GitHub warning

GitHub browser upload is not automatic and it has file-size limits. Large game assets should stay in Google Drive.

Suggested GitHub folders

scriptsSmall .gd files
scenesSmall .tscn scenes
screenshotsEvidence images
docsDev log and testing notes
small_assetsOnly small files
README.mdProject overview and links

How to make a folder in GitHub web

GitHub does not really use empty folders. To create a folder in the web editor, create a new file with a path such as docs/devlog.md or upload a folder that already contains files.

End-of-Class Checklist

Godot project saved
Master version tested
New assets uploaded to Google Drive
New code or feature handoff uploaded
Screenshot or bug evidence added
Daily dev log updated
GitHub checkpoint uploaded, if your group is using GitHub
Group knows the next task

Final rule

If the work is not saved in Google Drive or GitHub, it cannot be used as project evidence.

Minimum System for Beginners

If your group is overwhelmed, use this simple version:

1

One Drive folder

All group work goes into the shared folder.

2

One master project

Only the Integrator controls the main Godot project.

3

One task each

Every student owns one feature or asset job.

4

One daily log

Write what changed and what broke.

5

One final ZIP

Submit the final project through Drive/Classroom.
